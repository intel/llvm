# SYCL toolchain versions (RTC/JIT multi-version support)

This directory holds **frozen, vendored snapshots** of released SYCL toolchains
(headers + libdevice sources). They exist so the RTC/JIT device compiler
embedded in `libsycl-jit.so` can compile user SYCL source against **multiple
SYCL versions**, not just the current one. A single shipped driver can then
serve several SYCL versions (the version is chosen at runtime).

## Layout

```
sycl-toolchains/
  snapshot-version.sh        # tool that adds a new frozen version (see below)
  build-version-libdevice.sh # builds a version's device libs from its sources
  sycl-v-<label>/            # one frozen release, e.g. sycl-v-6.3.0/
    include/                 # sycl/, CL/, std/, unified-runtime/  (+ generated headers)
    libdevice/               # libdevice sources; built into per-version .bc at build time
    VERSION                  # provenance: label + ref + resolved commit SHA
```

Each `sycl-v-*/` is a self-contained slice of a released toolchain, captured via
`git archive` of that release's tag. `VERSION` records exactly which commit it
came from.

## "latest" is the current tree — it is NOT stored here

There is deliberately no `sycl-v-latest/` on disk. "latest" always tracks the
**live working tree** and is assembled at **build time** from the existing
`sycl-headers` + `libsycldevice` targets (the current headers, and the current
`libdevice.bc` the normal build already produces). The build stages that live
output alongside the frozen `sycl-v-*/` snapshots into one embed tree.

Consequence: you never hand-sync "latest". Committing new work to the tree moves
"latest" forward automatically; the frozen `sycl-v-*/` dirs stay pinned.

## Adding a version

```bash
./snapshot-version.sh <label> [<git-ref>]

# examples:
./snapshot-version.sh 6.3.0            # snapshots tag v6.3.0
./snapshot-version.sh 6.2.2 v6.2.2     # explicit ref
```

The script shallow-fetches the tag from the `intel` remote if it isn't present,
extracts the header + libdevice sources, and writes `VERSION`. The build's CMake
auto-discovers `sycl-v-*` dirs, so **adding a version = run the script + commit**.
**Dropping a version = delete its dir.** Which of the two you do is decided by
testing (see below).

To list candidate release tags:

```bash
git ls-remote --tags intel | sed 's,.*refs/tags/,,;s,\^{},,' \
  | sort -uV | grep -E '^v[0-9]+\.[0-9]+\.[0-9]+$'
```

Note: tag order != release date (e.g. `v6.2.2` shipped *after* `v6.3.0` as a
backport on the 6.2 branch). Choose LTS versions by supported branch, not by
version-number sort.

## Import once, then own the git history

`snapshot-version.sh` is a **one-time importer**. Run it once for a new version,
then `git add` + commit the result as the pristine import. From that point the
snapshot is **tracked source we maintain with normal git commits** — new-clang
compatibility fixes, etc. Git *is* the patch history; there is no separate
`patches/` mechanism. `VERSION` records the origin release SHA so you can always
see what diverged from upstream.

Do **not** `--force` re-import a version you have since modified: it restores the
pristine release and discards your tracked divergence.

Example first divergence already applied to v6.2.2 / v6.3.0: dropping the
`__SYCL_TYPE(buffer_location)` annotation (see the comment in
`include/sycl/properties/accessor_properties.hpp`). It is safe here because the
compiler feature it drove (FPGA `kernel_arg_buffer_location` metadata) was
removed in intel/llvm#22499, so the annotation is a no-op under the new compiler.
This judgement is **per-dropped-attribute**, not a blanket "strip annotations"
rule — verify a feature is actually gone before removing its tag.

## Promotion / drop policy (why these are here)

The decision to keep vs. drop a version is driven by the RTC E2E tests:
- all tests pass on a version -> safe to promote/drop the older one;
- a test fails on an undocumented behavior a consumer relied on -> keep the copy.

## What a snapshot contains (and how it is assembled)

`git archive` alone is not enough — the RTC toolchain needs headers that are not
committed source. The script assembles a *complete* snapshot per version:

- `include/{sycl,CL,std}` — committed source (`git archive`).
- `include/unified-runtime/` — the in-repo `unified-runtime` project's headers
  (`git archive`). Layout differs by release; see the include-path contract below.
- `include/sycl/device_aspect_macros.hpp` — regenerated by that release's own
  committed generator script.
- `include/sycl/{version,feature_test}.hpp` — produced by real `configure_file()`
  (`cmake -P`) of that release's `.in` templates.
- `libdevice/` — libdevice sources (`git archive`), compiled to `.bc` by the new clang.

## Per-version device libraries (`build-version-libdevice.sh`)

At build time, each version's `libdevice/` sources are compiled by the **new
clang** into the **same per-library `.bc` files the RTC loads by name** (see
`getDeviceLibraries` in `DeviceCompilation.cpp`), placed under
`sycl-v-<label>/lib/dpcpp-<major>/sycl/`:

- `libsycl-crt.bc`, `libsycl-cmath.bc`, `libsycl-imf.bc` — always loaded
- `libsycl-itt-{stubs,compiler-wrappers,user-wrappers}.bc` — only with
  `-fsycl-instrument-device-code` (device profiling; default off)
- `libsycl-fallback-bfloat16.bc`, `libsycl-native-bfloat16.bc` — only when a
  kernel uses bf16; loaded as *separate* device images

`cmath-fp64` / `complex` are intentionally not built — the RTC never loads them.

Design notes:
- **Separate named files, not one merged bitcode.** Keeping the upstream names
  means the runtime needs **no change** beyond its version-aware toolchain
  prefix: it finds each version's libraries exactly as it finds the live ones,
  links them with the same `LinkOnlyNeeded` semantics, and the bf16 device-image
  path works unchanged. A pre-merged bitcode would risk cross-library symbol
  collisions and cannot represent the bf16 libraries (they must stay distinct
  images).
- **Pinned per version.** Each version's libdevice is built from *its own*
  sources, so the implementation matches its headers. Sharing one libdevice
  across versions would break if a symbol's semantics changed or an
  implementation was removed between versions.
- The live "latest" tree needs nothing here — its `libsycl-*.bc` are already
  produced by the normal `libsycldevice` build and staged under `latest/lib`.

## Include-path contract

The `ur_api.h` include spelling changed across releases: older SYCL headers use
`#include <ur_api.h>`, newer ones `#include <unified-runtime/ur_api.h>`. Snapshots
always place UR headers under `include/unified-runtime/`, so the RTC build must add
**both** `-I <ver>/include` and `-I <ver>/include/unified-runtime` — then either
spelling resolves regardless of the version's age.

## Known caveats

- **Feature-test macros.** `feature_test.hpp` is generated with the `.in`
  template defaults (backend ext macros undefined -> 0). A shipped release may
  have enabled specific backend extensions. If a version's RTC tests depend on
  those, override the values in the script's `configure.cmake` block, or lift
  `feature_test.hpp` from that release's package.
- **Compiler drift (validated).** New clang can drop `sycl_type` attribute
  arguments that old headers use. Confirmed for v6.2.2/v6.3.0 under clang 7.2.0:
  `__SYCL_TYPE(buffer_location)` is rejected (removed from the `SYCLType` enum in
  `clang/include/clang/Basic/Attr.td`). This is the one real incompatibility
  found so far; libdevice compiles clean. Resolve per the promotion policy above.
